# 슬랙 알림

GitHub Actions(`.github/workflows/slack-notify.yml`)가 저장소 이벤트를 팀 슬랙 채널로 보냅니다.
메시지는 사람이 쓰지 않습니다. 아래 틀대로 `tools/slack_notify.py` 가 자동으로 채워서 올립니다.

## 메시지 구조

모든 알림은 같은 네 부분으로 되어 있어서, 맨 아래 줄만 봐도 누가 무엇을 해야 하는지 알 수 있습니다.

```text
*{이모지} {무슨 일}*            ← 1. 제목
<{링크}|#{번호} {제목}>         ← 2. 대상 (누르면 GitHub 로 이동)
• {항목}: {값}                 ← 3. 정보 (알림마다 다름)
👉 {누가}: {무엇을 해야 하는지}   ← 4. 다음 행동
```

## 메시지 틀

`{ }` 부분이 자동으로 채워집니다. 이름은 GitHub 아이디로 표시되며 슬랙 멘션은 걸리지 않습니다.

### PR 열림 / Draft 해제

```text
*📬 새 PR*
#{번호} {제목}
• 작성자: {아이디}
• 브랜치: {작업 브랜치} → {대상 브랜치}
• 변경: +{추가} / -{삭제} (파일 {개수}개)
• 리뷰어: {아이디 목록}
• 라벨: {라벨 목록}
👉 리뷰어: 24시간 안에 리뷰해 주세요
```

- 리뷰어가 없으면 `• 리뷰어: 없음` 으로 표시되고 다음 행동은 `👉 작성자: 리뷰어를 지정해 주세요` 입니다.
- `safety` 라벨이 있으면 `• ⚠️ 안전 파일: Approve 2명 + 테스트 클립 CROSS 0회 결과 첨부` 가 추가됩니다.
- Draft PR 은 보내지 않습니다.

### 리뷰어 지정

```text
*👀 리뷰어 지정*
#{번호} {제목}
• 리뷰어: {아이디}
• 작성자: {아이디}
• 변경: +{추가} / -{삭제} (파일 {개수}개)
👉 {아이디}: 24시간 안에 리뷰해 주세요 (마감 24시간 이내 PR 은 2시간)
```

- 리뷰어 한 명마다 한 건씩 옵니다.
- `safety` 라벨이 있으면 `• ⚠️ 안전 파일: Approve 2명 + 테스트 클립 CROSS 0회 결과 첨부` 가 추가됩니다.

### 승인

```text
*👍 승인*
#{번호} {제목}
• 리뷰어: {아이디}
• 작성자: {아이디}
• 남은 리뷰어: {아이디 목록}
👉 작성자: 머지 조건을 확인하고 Squash and merge 해 주세요
```

- `safety` 라벨이 있으면 `• ⚠️ 안전 파일: Approve 2명 + 테스트 클립 CROSS 0회 결과 첨부` 가 추가됩니다.

### 수정 요청

```text
*✋ 수정 요청*
#{번호} {제목}
• 리뷰어: {아이디}
• 작성자: {아이디}
• 내용: {리뷰 본문 첫 줄, 100자까지}
👉 작성자: [must] 코멘트를 해결하고 리뷰를 다시 요청해 주세요
```

- 리뷰 본문이 비어 있으면 `내용` 줄은 빠집니다.
- 일반 코멘트 리뷰는 보내지 않습니다.

### 머지

```text
*✅ 머지 완료*
#{번호} {제목}
• 작성자: {아이디}
• 머지한 사람: {아이디}
• 브랜치: {작업 브랜치} → {대상 브랜치}
• 변경: +{추가} / -{삭제} (파일 {개수}개)
👉 모두: 새 작업 전에 main 을 최신으로 받아 주세요 (git pull)
```

- 머지 없이 닫힌 PR 은 보내지 않습니다.

### 이슈 열림

```text
*📝 새 이슈*
#{번호} {제목}
• 작성자: {아이디}
• 담당: {아이디 목록}
• 라벨: {라벨 목록}
👉 담당자: 완료 조건을 확인해 주세요
```

- 담당자가 없으면 `• 담당: 없음` 으로 표시되고 다음 행동은 `👉 작성자: 담당자를 지정해 주세요` 입니다.
- 팀원이 연 이슈만 보냅니다.

### main CI 실패

```text
*🚨 main CI 실패*
커밋 {짧은 해시} 실행 기록
• 커밋: {커밋 메시지 첫 줄, 100자까지}
• 올린 사람: {아이디}
👉 머지한 사람: 먼저 GitHub Revert, 그다음 fix/ 브랜치로 다시 PR 하세요
```

- PR 의 CI 실패는 보내지 않습니다.

## 예시

리뷰어를 지정하고 `safety` 라벨을 단 PR 은 슬랙에 이렇게 보입니다.

```text
📬 새 PR
#7 feat(#7): add BLINK state to signal FSM
• 작성자: kyobak
• 브랜치: feat/7-signal-fsm → main
• 변경: +120 / -4 (파일 3개)
• 리뷰어: ParkJiSeong901
• 라벨: logic, safety
• ⚠️ 안전 파일: Approve 2명 + 테스트 클립 CROSS 0회 결과 첨부
👉 리뷰어: 24시간 안에 리뷰해 주세요
```

## 틀을 바꾸려면

1. `tools/slack_notify.py` 의 해당 함수에서 제목, 정보 줄, 다음 행동을 고칩니다. 구조는 `render()` 한 곳에 있습니다.
2. 이 문서의 틀과 `tests/test_slack_notify.py` 를 같이 고칩니다.
3. PR 로 올립니다(`CONTRIBUTING.md` 3절).

알고 있는 동작: PR 을 만들면서 리뷰어를 함께 지정하면 📬 새 PR 과 👀 리뷰어 지정이 모두 옵니다. 포크에서 온 PR 은 시크릿을 받지 못해 알림이 가지 않습니다. 팀원은 저장소 안 브랜치로 작업합니다(`CONTRIBUTING.md` 1절).

## 처음 한 번 설정 (저장소 관리자)

1. <https://api.slack.com/apps> → **Create New App** → **From scratch** → 팀 워크스페이스 선택
2. **Incoming Webhooks** 켜기 → **Add New Webhook to Workspace** → 알림 채널 선택 → URL 복사
3. 저장소 폴더에서 아래 명령을 실행하고, 물어볼 때 URL 을 붙여 넣기

```bash
gh secret set SLACK_WEBHOOK_URL --repo kyobak/teamproject_aix_team09
```

웹훅 URL 은 비밀번호와 같습니다. 코드·문서·채팅에 남기지 마세요. 유출되면 슬랙 앱 설정에서 웹훅을 지우고 새로 만든 뒤 위 명령을 다시 실행합니다.

## 확인과 문제 해결

- 시크릿을 넣은 뒤 PR 을 하나 열면 채널에 📬 메시지가 옵니다.
- 메시지가 없으면 저장소 **Actions → Slack Notify** 의 실행 기록을 봅니다.
- `main` CI 실패 알림은 이 워크플로가 `main` 에 머지된 뒤부터 동작합니다(`workflow_run` 은 기본 브랜치의 파일만 실행).
- 채널을 바꾸려면 새 채널로 웹훅을 다시 만들어 시크릿을 교체합니다.
