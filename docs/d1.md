# D1 사전학습 YOLO 검출기 (#12)

D1은 COCO 사전학습 YOLO11n으로 신호등 박스를 찾고 기존 classify_signal()로 색을 판정하는 비교용 구현입니다. D0와 같은 Detector 인터페이스와 SceneState를 반환합니다.

## 설치와 실행

프로젝트 루트에서 실행합니다. 공통 NumPy·OpenCV 버전은 requirements.txt에 고정하며 YOLO는 선택 설치합니다.

```powershell
& "..\.venv\Scripts\python.exe" -X utf8 -m pip install -r requirements-yolo.txt
& "..\.venv\Scripts\python.exe" -X utf8 -c "from ultralytics import YOLO; model=YOLO('models/yolo11n.pt'); print(model.names[9])"
& "..\.venv\Scripts\python.exe" -X utf8 -m walkaid.main --source data/sample.mp4 --detector d1
```

macOS/Linux는 가상환경 활성화 후 python으로 같은 모듈·인자를 실행합니다. 음성 출력은 기존 --tts 옵션을 사용합니다.

- 설치 버전: ultralytics 8.4.213. 모델은 공식 YOLO11n COCO 가중치이며 models/yolo11n.pt에 보관합니다.
- 모델이 없으면 실행 중 자동 다운로드하지 않고 오류를 냅니다. 위의 명시적인 다운로드 명령을 먼저 실행합니다.
- D0 실행과 합성 테스트는 Ultralytics·모델 없이도 가능합니다. 실제 D1 추론에는 선택 의존성과 모델이 필요합니다.
- 모델·영상·사진은 Git에서 제외합니다.

## 동작

1. 기본적으로 화면 위쪽 65%를 YOLO에 전달합니다. 입력 크기 640, 검출 conf 0.25, CPU로 시작합니다.
2. 모델의 names에서 traffic light 클래스 ID를 찾아 그 클래스만 사용합니다. 보행 색이나 팀 라벨 0~5와 COCO ID를 혼동하지 않습니다.
3. 짧은 변 8픽셀 미만과 높이/폭 비율 1.8~4.5 밖의 박스를 제외합니다. 가로 차량 신호등을 제외하는 형태 필터이며 세로 차량 신호등까지 구분한다는 뜻은 아닙니다.
4. 박스의 원본 BGR 픽셀을 기존 3칸 색 판정 함수에 전달합니다. signal.conf는 기존 함수의 색 판정 확신도이고 YOLO의 박스 확신도와는 별도입니다.
5. 처음에는 가장 큰 후보를 고릅니다. 면적이 최대 후보의 75% 이상인 후보들의 색이 다르면 unknown으로 둡니다.
6. 최근 2.5초 안에 보던 대상이 있으면 몸체 폭의 0.6배 이내 후보만 다시 찾습니다. 갑자기 다른 위치의 초록 신호로 옮겨 가는 것을 억제합니다.
7. SceneState 뒤의 상태 머신·안내는 기존 구현을 사용합니다. YOLO 출력으로 CROSS를 직접 결정하지 않습니다.

설정은 기본값으로 실행할 수 있습니다. 테스트나 별도 호출에서 config 딕셔너리의 d1에 weights/conf/imgsz/device/roi_height를 넘길 수 있습니다. config.yaml과 안전 파일은 이번 작업에서 수정하지 않습니다.

## 웹캠 CPU 속도

2026-11-24 강태혁 로컬 Windows 노트북(Intel Core Ultra 9 275HX)에서 내장 웹캠과 CPU로 예비 측정했습니다. 시연 노트북과 같은 기기인지는 확인하지 않았습니다.

| 검출기 | 웹캠 입력 포함 FPS | 검출·상태 판단 평균(ms) | 검출·상태 판단 p95(ms) |
|---|---:|---:|---:|
| D0 | 30.49 | 3.16 | 3.65 |
| D1 | 29.89 | 16.60 | 20.12 |

두 검출기 모두 웹캠 640×480, 준비 프레임 5장 이후 60장을 측정했습니다. 웹캠 입력 포함 FPS는 프레임 읽기·검출·상태 판단의 총 시간 기준입니다. 음성·시연 화면은 끄고 입력 속도 제한을 해제했습니다. D1은 기본 CPU와 `imgsz=640`을 사용했습니다. 기본 앱의 5fps 제한이나 전체 안내 지연을 측정한 수치는 아닙니다.

시연 노트북에서도 같은 해상도·조건으로 D0·D1을 다시 측정합니다. 시연 입력 크기에서 프레임 처리가 목표 속도에 못 미치면 축소한 입력 크기로 속도와 정확도를 다시 비교한 뒤 설정을 결정합니다.

## 한계와 평가

- COCO 기본 모델에는 ped_red/ped_green/ped_off/car_signal의 구분이 없습니다. 한국 보행 신호등 검출과 세로 차량 신호등 제외 성능은 실제 평가가 필요합니다.
- YOLO 박스가 기존 색 판정 함수가 기대하는 세로 3칸 전체 몸체와 맞지 않으면 unknown 또는 잘못된 색이 나올 수 있습니다.
- 이 구현의 실행 성공이나 합성 테스트 통과를 실제 보행 성능으로 해석하지 않습니다.
- docs/eval.md의 D0 평가 12개 영상과 동일한 프레임·정답표로 D1을 측정해야 #12의 평가 조건을 완료할 수 있습니다.
- #38에서 12개 영상의 파일명·정답·박스를 담은 data/labels/signal_eval_gt.json과 공통 평가 스크립트 tools/eval_signal.py가 main에 추가됐습니다. 평가 영상 파일과 정답 파일의 대응을 확인한 뒤 같은 자료로 D0·D1을 실행해야 합니다. 데이터 보관과 접근 규칙은 [ETHICS.md](../ETHICS.md)를 따릅니다.

## #38 공통 평가 스크립트 사용

아래 data/eval-videos는 정답 파일에 적힌 12개 영상이 있는 폴더로 바꿉니다. 블러 처리본을 사용하면 그 처리 버전도 함께 기록하고 D0·D1 모두 같은 파일을 사용합니다.

```powershell
& "..\.venv\Scripts\python.exe" -X utf8 tools/eval_signal.py --videos data/eval-videos --detector d0 --out data/d0-eval.json
& "..\.venv\Scripts\python.exe" -X utf8 tools/eval_signal.py --videos data/eval-videos --detector d1 --out data/d1-eval.json
```

macOS/Linux:

```bash
python tools/eval_signal.py --videos data/eval-videos --detector d0 --out data/d0-eval.json
python tools/eval_signal.py --videos data/eval-videos --detector d1 --out data/d1-eval.json
```

평가는 30fps와 원본 해상도를 기준으로 좌표와 정답 시각을 해석합니다. 지성의 노트북에서 정답표와 동일한 파일명·해상도·프레임 속도의 원본 12개를 확인하고, 원본은 로컬에 둔 채 두 명령을 같은 폴더에 실행합니다. 검출 상자가 빨강·초록 두 칸만 포함하는지 숫자 칸도 포함하는지는 해당 노트북에서 실제 평가 화면을 확인해 기록합니다.

스크립트는 없는 영상을 건너뛰므로 실행 성공만으로 12개 전부 평가했다고 판단하지 않습니다. 결과 JSON의 longest_red_green 파일 목록이 정답 파일의 12개와 모두 일치하는지 확인합니다. D1은 last_box를 제공하므로 공통 스크립트에서 위치 판정도 수행합니다. 예전 D0 수치와 다른 버전의 블러 영상에서 얻은 D1 수치를 직접 비교하지 않습니다.
